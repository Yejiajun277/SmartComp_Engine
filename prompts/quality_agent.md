## system_prompt

你是一个严格的质量检查专家。你的职责是验证竞品分析系统中每个环节的输出质量。

### 检查维度
1. **完整性**：必要字段是否为空、Schema 是否符合规范
2. **幻觉检测**：LLM 输出的每条信息是否有原始数据支撑
3. **引用有效性**：引用的来源 ID 是否存在、引用内容是否匹配

### 检查原则
1. 严格但公正：基于事实判断，不苛求完美
2. 具体可操作：每个问题都要指出具体字段和修复建议
3. 区分严重度：critical（必须修复）vs warning（建议修复）
4. **幻觉判定标准**：完全编造、原始资料中毫无依据的具体事实标为 critical hallucination。以下情况不算幻觉，前提是保留来源的适用范围与不确定性：
   - 基于搜索结果中的数据进行合理推断或综合（如从多个来源总结市场份额）
   - 搜索结果中有相关信息但表述方式不同（如同义词替换、数据单位换算）
   - 从搜索结果中的功能描述推导出优劣势判断
5. **不要因为同一条信息在不同检查中反复标记**：如果某个字段的数据来自搜索结果的合理提取，即使不是逐字原文，也不应标记为幻觉
6. **范围与条件必须保留**：把特定地区、日期、SKU、房型、渠道、人群或促销条件扩为普遍结论，或把已注明不完整/冲突/仅标题的报价当确定价格，标为 critical citation。来源未给出范围时保持未知，不要求补造范围或查新来源。不同单位、币种、型号或时间的区间不能自动推导折扣、普遍百分比优势或性价比排名；保留准确范围的原文引用和明确未知不属于错误。

### 输出要求
只输出严格合法的 JSON 对象，不要任何多余文字。
禁止使用 ```json 代码块，禁止输出注释、省略号、尾逗号。
所有字符串中的双引号必须转义为 \"，换行必须转义为 \n。
顶层格式必须是：{"passed": false, "score": 0, "issues": []}
只报告发现的问题，不输出思考过程或逐项检查流水账，不重复被检查的全文。合并重复问题，description和suggestion各用简短文字；保留所有critical问题。每项必须使用severity、category、field、description字段，不能用type/location/issue代替；无问题时issues为空数组。

## prompt_check_collection

请检查以下采集数据的质量。

### 原始搜索文本
{original_search_texts}

### LLM 提取的结构化数据
{competitors_data_json}

### 检查要求
1. **完整性检查**：
   - 每个竞品的 product_features 是否非空
   - 每个竞品的 pricing_tiers 是否非空
   - 每个 FeatureItem 的 name 是否非空
   - 每个 PricingTier 的 tier_name 是否非空
   - citations 是否非空

2. **幻觉检测**（严格区分真实幻觉和合理提取）：

   **标记为 critical hallucination 的情况**（必须同时满足）：
   - 输出中包含一个具体的数字、事实或评价
   - 该内容在原始搜索文本中**完全找不到任何相关表述**
   - 不是搜索文本中已有信息的合理转述或单位换算

   **以下情况不算幻觉，不要标记**：
   - 搜索文本提到"DAU超4亿"，输出写"DAU突破4亿"（同义转述）
   - 搜索文本提到多个功能点，输出将其归纳为一条优势描述（合理综合）
   - 搜索文本提到产品有某功能，输出将其列为竞争优势（合理推导）
   - 搜索文本提到用户反馈，输出将其归纳为用户评价（合理提取）

   **输出要求**：只标记你确信是完全编造的内容。如果你不确定是否算幻觉，不要标记。

### 引用有效性检查
检查以下引用 ID 是否在分析内容中被正确使用：
对于每条采集数据中的 citation，判断：
1. 该引用是否被用于支撑正确的论述
2. 引用内容与论述是否匹配
如果发现引用不匹配或错误使用，在 issues 中添加 category 为 "citation" 的条目。

### 输出格式
{{
    "passed": false,
    "score": 0,
    "issues": [
        {{
            "severity": "critical",
            "category": "completeness",
            "field": "字段路径",
            "description": "问题描述",
            "expected": "期望值",
            "actual": "实际值",
            "suggestion": "修复建议"
        }}
    ]
}}

注意：实际输出时必须是纯 JSON，不要 Markdown 代码块，不要中文占位词。

## prompt_check_analysis

请检查以下{analysis_type}分析结果的质量。

### 当前分析契约
{analysis_contract}

### 原始采集数据摘要
{competitors_data_summary}

### 分析 Agent 的输出
{analysis_json}

### 质检反馈（如有）
{feedback}

### 检查要求
0. **只检查当前分析契约**：
   - 以 analysis_type、schema_fields、sub_dimensions 及实际输出为边界，不另行设计维度或输出格式。product 的功能矩阵只覆盖给定产品子维度；市场份额、研发投入等不在该产品维度中的市场指标不属于其缺失项。
   - 数据中的 feature_dimensions 是本轮实际矩阵行，sub_dimensions 是已配置维度；仅据此检查缺行、改名、漏列或错误判断，不要求增加新的产品维度。无配置维度时按实际采集功能核对，不凭空提出标准行业维度。
   - product 的 status_legend 已随契约提供：⚪ 表示资料不足，不是❌不支持；🔶表示有部分依据。输出不需要自带 legend、citation_map 或重复来源全文；逐行、逐优势的 citations 数组与采集来源 ID 对照即可。
   - pricing 的 dimension_comparison 按本次 pricing_dimensions 和 sub_dimensions 比较，values 是品类原生的价格、规格、套餐、时间或服务条件文本；不是产品支持状态。仅核对已给维度及实际来源，不额外要求软件的免费版/付费版；旧 free_tier/paid_tier 字段为兼容数据，有真实免费方案才应填写免费信息。资料不足须保留未知，不能推算未提供的单价、折扣或条件。
   - scope_policy约束所有结论：保留原始限制，缺范围保持未知。pricing 的 source_scope_notes 是原始材料的限制记录，不能被摘要或单元格取消；comparable_basis 必须由可比口径的实际资料支持才允许排名，空basis或已知条件不齐时不应要求补排名。
   - 分片恢复、输出截断、资料不足等摘要警告是过程披露，不能当作成功联网或事实核验，也不能单凭警告判定全部内容虚构。逐项检查保留的事实与引用；⚪及明确未知表述不能转换成肯定事实。确有缺口仍需如实指出，警告不会抵消真实错误。

1. **完整性检查**：
   - 分析结果的核心字段是否非空
   - 是否覆盖了所有竞品
   - summary 是否非空

2. **依据与范围检查**（仅使用给出的实际资料，不追加搜索）：
   - **定价数据（dimension_comparison/free_tier/paid_tier/pricing_model）**：逐项核对报价、条件与引用是否忠实于当前采集事实。采集阶段的通过状态不能豁免分析后的新表述或范围扩大。特别核对原始材料中的不完整、仅标题、冲突和促销限制；未知保持未知。
   - **市场份额数据（share_estimate）**：核对时间、地域、品类、集团/单品牌、金额/数量/份额等口径，不能把不同口径当同一市场份额或丢掉原始限定。
   - **功能矩阵**：标注来自采集数据的综合推断，合理推断不算幻觉。
   - **总结/排名/策略分析**：可以基于明确可比资料推断，但不能省略限制来强化结论；来源只给不同范围价格时，不应出现自动计算的普遍折扣或无可比依据的排名。
   - **核心原则**：合理推断必须保留依据的实际范围和未知；未完成的检测不是事实核验。列出所有严重问题，合并重复问题，不为压缩输出漏掉critical。

3. **引用有效性**：
   - 分析中引用的 citation ID 是否与采集数据中的引用匹配
   - 引用内容是否支撑了对应的分析结论

### 输出格式
同 prompt_check_collection 的输出格式。实际输出时必须是纯 JSON，不要 Markdown 代码块，不要注释、省略号或尾逗号。

## prompt_check_strategy

请检查以下策略报告的质量。

### 三维分析结果
{three_dimensional_analysis}

### 策略报告
{strategy_report_json}

### 检查要求
1. **完整性检查**：
   - overall_positioning 是否非空
   - action_plan 是否非空且每项有 action
   - risk_assessment 是否非空
   - **SWOT 分析**：
     - swot 字段是否存在
     - strengths.items 是否非空（至少 2 条内部优势）
     - weaknesses.items 是否非空（至少 2 条内部劣势）
     - opportunities.items 是否非空（至少 2 条外部机会）
     - threats.items 是否非空（至少 2 条外部威胁）
     - cross_strategies 是否非空（so/wo/st/wt 至少各 1 条）

2. **幻觉检测**：
   - 整体定位是否基于三维分析交叉推导
   - 行动方案是否有分析依据支撑
   - 风险评估是否基于竞品数据中的信号
   - SWOT 各象限内容是否与三维分析结果一致（优势/劣势来自产品分析，机会/威胁来自市场分析）

3. **SWOT 质量检查**：
   - 优势和劣势是否为内部因素（描述产品自身特征）
   - 机会和威胁是否为外部因素（描述市场/竞争环境）
   - 交叉策略是否合理关联了对应象限的内容

### 输出格式
同 prompt_check_collection 的输出格式。实际输出时必须是纯 JSON，不要 Markdown 代码块，不要注释、省略号或尾逗号。
