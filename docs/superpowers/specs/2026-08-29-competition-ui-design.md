# SmartComp Engine 比赛版前端设计

- 日期：2026-08-29
- 基线：`final_work` / `origin/final_work`，提交 `5236690`
- 开发分支：`codex/competition-ui`
- 设计状态：方向 1“证据驱动的策略指挥舱”已获用户确认；用户授权由主 Agent 完成后续视觉与产品取舍

## 1. 目标

把现有“功能完整但像默认管理后台”的 Web UI，重构成适合课堂展示、学生使用和比赛评审的专业产品体验。页面需要在 30–90 秒内主动讲清以下故事：

1. 用户输入一个产品或产品描述。
2. 七个专职 Agent 串并行协作完成竞品发现、数据采集、维度配置和三维分析。
3. QualityAgent 在关键阶段执行质量门检查，失败时打回对应 Agent 修正。
4. 分析结论保留引用链和质量指标，可以追溯而非只生成文本。
5. 最终交付一份决策优先、可执行、带证据的策略报告。

第一阶段只改变前端体验和报告入口的呈现方式，复用现有 REST、WebSocket、任务模型、QA 产物和 HTML 报告，不引入新的权限、数据库或工作流编排系统。

## 2. 体验原则

### 2.1 先讲价值，再暴露技术

首页先说明“多 Agent 协作 + QA 自纠错 + 引用追溯”的价值；规则引擎、跳过 QA 等工程开关收进高级设置，避免让首次使用者先做技术选择。

### 2.2 把 QA 设计成流程，而不是附属日志

工作台把 QualityAgent 显式呈现为质量门。QA 失败、反馈、打回、重试和降级通过都必须在主流程上可见，而不是只存在于下方时间线。

### 2.3 先给决策，再给完整材料

报告入口首屏先回答“建议做什么、为什么、可信度如何”，然后再进入完整 HTML 报告、技术追溯和 JSON 数据。

### 2.4 专业克制的视觉冲击

以深海军蓝、石墨黑为工作台底色，电光青和靛紫表达 Agent 数据流，琥珀色表达 QA 风险，薄荷绿表达通过。动效服务于状态变化和流程方向，不采用持续炫光或游戏化效果。

## 3. 信息架构

应用保持三条既有路由，不新增后端路由：

- `/`：分析中心。品牌首页、任务创建、方法证明和近期任务。
- `/tasks/:taskId`：实时 Agent 工作台。任务状态、流程、QA、事件和技术追溯。
- `/tasks/:taskId/report`：策略报告中心。决策摘要、可信度概览、完整报告和 JSON。

顶部应用外壳统一包含：

- SmartComp 品牌标识与一句话定位。
- “分析中心”主导航。
- 为未来老师端、学生端预留的“教学 / 比赛模式”信息标签；第一阶段不实现账号或角色切换。
- 全局状态使用文字、图标和颜色共同表达，避免仅依赖颜色。

## 4. 页面设计

### 4.1 分析中心：首页与任务创建

采用“聚焦启动”的叙事型布局：

1. 首屏左侧为价值主张：“把竞品分析交给一支会互相质检的 Agent 团队”。下方显示七个 Agent、三路并行分析、结论可追溯三项证明。
2. 首屏右侧为任务启动面板。默认只展示产品描述和竞品数量；QA 默认开启。规则引擎、跳过 QA 收进“高级设置”。跳过 QA 需要使用风险文案，而不是中性开关。
3. 首屏下方用五步故事条呈现“发现竞品 → 采集证据 → 并行分析 → QA 打回 → 策略交付”。
4. 近期任务使用紧凑卡片或表格，突出产品、状态、当前阶段、质量分数/引用数量和主要行动按钮。删除操作弱化并保持确认。
5. 空状态提供三个示例产品快捷填入，不自动提交。

### 4.2 实时 Agent 工作台

桌面端采用“主流程 + 侧边实时轨道”的布局：

- 顶部任务指挥条：产品、状态、连接状态、总进度、当前动作和报告入口。
- 主区域左侧约三分之二：可视化流水线。
- 主区域右侧约三分之一：实时事件流，突出当前 Agent 正在做什么、最近一次 QA 结论和证据采集数量。
- 下方：质量驾驶舱与技术追溯。

流水线结构保持业务真实顺序：

1. DiscoveryAgent：竞品发现。
2. CollectionAgent：证据采集。
3. QualityAgent Gate：采集质检。
4. DimensionAgent：维度配置。
5. ProductAgent / PricingAgent / MarketAgent：三路并行。
6. QualityAgent Gate：三维分析质检。
7. StrategyAgent：策略综合。
8. QualityAgent Gate：报告质检与交付。

每个业务节点显示等待、运行、完成、重试、失败状态。QA Gate 显示分数、问题数、重试次数和降级状态。失败后使用回流连线和明确文案指向被打回的 Agent；在窄屏中改为纵向时间线，并在对应节点内显示“被 QA 打回”。

Agent 详情继续使用抽屉，但内容顺序调整为：阶段摘要、产物、质量反馈、证据/引用、技术原始数据。System Prompt 和完整 LLM 输出默认折叠在“技术追溯”中。

质量驾驶舱展示：

- 最新有效检查的准确率、覆盖率和修正率。
- 总 QA 次数、累计打回次数、是否发生降级通过。
- “修正前问题 → QA 反馈 → 修正结果”的时间线摘要。

### 4.3 策略报告中心

保留现有 HTML 报告生成器和 iframe，避免第一阶段重写报告系统。React 页面在 iframe 之前增加决策层：

- 报告头部：产品、竞品数量、生成状态和返回工作台入口。
- 核心定位：`overall_positioning`。
- 三张决策卡：P0/P1 优先行动、预期影响和时间范围。
- 可信度条：引用数量、QA 检查数量、最终通过/降级状态；数据不足时如实显示，不伪造总分。
- 视图切换：决策简报、完整报告、JSON 数据。默认打开决策简报，并在其后直接承接完整报告入口。
- 完整报告 iframe 使用统一容器、加载态、错误态和全屏打开按钮。

第一阶段不新增 PDF、Word 或复杂图表导出；保留现有 JSON 下载。

## 5. 视觉系统

### 5.1 色彩

- 页面底色：`#050B14` / `#07111F`。
- 卡片底色：`#0B1728` / `#0E1C30`。
- 主强调：电光青 `#55D9FF`。
- 协作强调：靛紫 `#8C7CFF`。
- QA 风险：琥珀 `#FFBD59`。
- 成功：薄荷绿 `#62E6B1`。
- 错误：珊瑚红 `#FF6B72`。
- 报告阅读区使用浅色纸面 `#F7F9FC`，通过相同青色/靛紫色和品牌图形保持一致。

### 5.2 排版与空间

不引入联网字体。使用系统无衬线字体栈，标题强化字重和紧凑字距，正文保持 1.6–1.75 行高。页面最大宽度约 1440px，8px 基础间距，卡片圆角 14–20px，边界主要依靠低透明描边而非重阴影。

### 5.3 品牌图形

品牌标识使用由两个错位方块和中心节点构成的简单 CSS/SVG 图形，表达“多 Agent 汇聚”。保留现有图标库，但移除 Vite/React 脚手架资源的产品露出。

## 6. 动效与响应式

- 页面进入：200–350ms 的淡入和轻微位移。
- 活跃 Agent：柔和脉冲和进度扫光。
- QA 打回：一次性回流动画，随后静态保留状态线索。
- 卡片与按钮：120–180ms 状态反馈。
- 支持 `prefers-reduced-motion`，关闭非必要运动。
- 断点：桌面 `>=1200px`、平板 `768–1199px`、手机 `<768px`。
- 手机端首页改为单列；工作台改为纵向流程；表格改为卡片或横向滚动；主要按钮保持可触达且不使用固定宽度。

## 7. 数据流与兼容策略

继续使用现有 `client.js`、`useTask` 和 `useWebSocket`：

- REST 提供任务列表、任务详情、阶段产物、QA 产物、报告和日志。
- WebSocket 驱动 Agent 状态、进度、QA 和日志更新。
- 页面仅计算展示派生值，例如引用数量、累计打回、最终 QA 状态；不改变后端业务含义。
- 页面刷新后继续从任务详情与归档产物恢复状态。
- API 字段缺失时使用明确空状态，不用演示数字填充真实任务。

## 8. 错误与降级体验

- WebSocket 断开：显示“实时连接中断，正在重连”，REST 轮询结果仍可阅读。
- API 列表加载失败：保留本地近期任务并显示非阻塞提示。
- 任务失败：在工作台顶部显示失败阶段和错误摘要，保留已生成产物。
- QA 降级通过：使用琥珀色和解释文案，不与正常通过混淆。
- 报告尚未生成：显示当前阶段和返回工作台按钮。
- iframe 加载失败：提供重新加载和新窗口打开入口。

## 10. 验证与验收

实施阶段采用最小、针对性验证：

1. 前端依赖只在需要构建时安装到 `frontend/node_modules`。
2. 运行前端 lint 与 production build。
3. 使用静态/模拟 API 数据检查首页、运行中工作台、QA 打回、完成报告、失败和空状态。
4. 检查 1440px、1024px、390px 三种视口。
5. 检查键盘焦点、状态文案、对比度和减少动效模式。
6. 如未修改 Python，不运行完整后端测试与真实 LLM/联网流水线；最终交付明确列出未运行项目。

验收标准：

- 首页首屏能在 30 秒内说明系统价值和五步闭环。
- 工作台首屏同时看见当前 Agent、并行关系、QA Gate 和打回状态。
- 报告首屏先出现核心定位、优先行动和可信度证明。
- 关键流程在手机端无内容遮挡或不可达操作。
- 不破坏现有任务创建、实时事件、阶段详情、报告和 JSON 下载功能。
